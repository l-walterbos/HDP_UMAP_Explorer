# Interactive UMAP explorer

This interactive app explores [UMAP](https://umap-learn.readthedocs.io/en/latest/) projections from our pernding publication (see our [preprint](https://doi.org/10.48550/arXiv.2606.11928)). For full details on data generation and processing, see our paper and the associated code on [GitHub](https://github.com/Luccerboi/HDP_WorkFLow_Analysis). In short, we performed high-throughput simulations on Halide Double Perovskites (HDPs, formula A2BB'X6) and used UMAP to reveal trends in electronic-structure data. The underlying data comes from our HDP DataBase available on [NOMAD](http://doi.org/10.17172/nomad.wb9y-b8j7)

The explorer is built with [Dash](http://dash.plotly.com) and lets you switch between several precomputed UMAP projections (`Precomputed_UMAPprojections_*.csv`). Our projections use projected Density of States and COHP curves, aligned on equal energy axes and presented in several formats. The app also supports coloring the projection by bandgap, net spin, lattice constants, and more. Clicking a point shows important simulated quantities for that composition and displays the corresponding DOS and COHP/COBI plots. A periodic table plot is also included, colored by averaged B-site element values.

## Running the explorer

1. Create a Python environment using **Python 3.13**
2. Install dependencies from `requirements.txt`
3. Run:
   ```bash
   python app.py
   ```

The app will run locally and let you explore the data.

## Available data and preparation

Parsed pDOS, pCOHP, and pCOBI data are available in JSON format in:
- `lsodos_smeared`
- `cohps_smeared`
- `cobis_smeared`

These files are the basis for the UMAP projections and are also used for the supplementary figures shown below the UMAP plot. All directories contain `smeared` because we added Gaussian smearing (0.05 eV) to smooth sharp peaks.

The file `HDP_CombinedInfo_260419.csv` is read as a pandas DataFrame and provides the values used for coloring the UMAP projection and periodic table. The CSV index (`index_col=0`) is used to access the correct composition data across plots. The index is `CompID`, structured as `XXXX_CsBB'X`, where `XXXX` is a unique number starting from 1000 and B, B', and X vary for each composition. For precise column definitions, see the linked paper.

To build the UMAP inputs, we equalize all curves across compositions. VASP and LOBSTER let you choose the number of energy points, but the energy range varies. We use a binning/fingerprinting method to sum contributions from the original energy axis into a common axis. This method is adapted from:

- [Purcell et al., 2023](http://doi.org/10.1038/s41524-023-01063-y)
- [Kuban et al., 2024](http://doi.org/10.1039/D4DD00258J)

The data preparation is in `dos_dataprepare.py`. It bins both pDOS and pCOHP and limits curves to 5 eV below the VBM and 5 eV above the CBM. The new energy axis runs from -5 to `(Max(CBM) + 5)`, but each composition only includes data from -5 to its own `CBM + 5`; values outside that range are set to zero.

DOS fingerprints are saved for total and projected site components (A/B1/B2/X), separately for spin-up and spin-down. The pCOHP fingerprints cover the 2 × 6 B–X bonds and include:
- 6-bond average
- bond averages aligned with each Cartesian axis
- spin-up and spin-down separately

These fingerprints are saved under `smeared_histogrammed_*` as CSVs, with energy-bin centers as the index and `CompID` columns. They are stored separately so different data combinations are easy to test.

## UMAP projections

Projections are generated by `umap_preparation.py`. It reads the fingerprinted data and defines a dataset dictionary. Each entry must be either a `pd.DataFrame` or a `list[pd.DataFrame]`. If a list is used, the code projects each DataFrame separately and then combines the projections using the intersection operator. Currently only list lengths of 2 and 4 are supported, and the combination operator is fixed.

We use these dataset conventions (here {data1,data2} indicates that those dataset are concatonated into one DataFrame an projected):
- `TDOS`: `{tdos_up, tdos_down}`
- `B-site pDOS`: `{pDOS(B1)_up, pDOS(B1)_down} * {pDOS(B2)_up, pDOS(B2)_down}`
- `Alternative B-site pDOS`: `{pDOS(B1)_up, pDOS(B2)_up} * {pDOS(B1)_down, pDOS(B2)_down}`
- `Separated B-site pDOS`: `{pDOS(B1)_up} * {pDOS(B1)_down} * {pDOS(B2)_up} * {pDOS(B2)_down}`
- `(6 bond) Average B-X pCOHP`: `{pCOHP(B1-X)_up, pCOHP(B1-X)_down} * {pCOHP(B2-X)_up, pCOHP(B2-X)_down}`

Each dataset also has a normalized variant (`norm_`), where each fingerprint area is scaled to 0.

We also define metric and nearest-neighbor lists:
- Metrics: `euclidean`, `seuclidean`, `manhattan`, `wminkowski`, `bray-curtis`, `cosine`
- Nearest neighbors: `5`, `15`, `25`, `50`, `100`
- `min_dist` is set to `0.1` for all projections

The script saves the results to `Precomputed_UMAPprojections_*.csv`, with `CompID` as the index and a MultiIndex of `[dataset, metric, nn_value, x/y]` as columns.

## Adding or adapting projections

The interactive viewer loads the precomputed UMAP CSV and populates:
- dataset dropdown
- metric radio buttons
- nn slider

If you want to add new projections, add your data and metrics to the dataset dictionary and metric list.

You can also use any dimensionality reduction method as long as the CSV keeps:
- `CompID` index
- 4-layer MultiIndex columns
- `x` and `y` as the lowest level

This allows the viewer to display projections from other methods without changing the app code.

If you adapt the viewer for another dataset, it should still be relatively easy as long as you keep a consistent index and file naming convention. Differences in parsing may still cause errors.
